# Руководство по LinkerMor

Справочник по возможностям, командам и развёртыванию.

---

## 1. Требования к серверу

### Измеренное потребление

Цифры получены на реальной сборке, а не оценены:

| Компонент | Память |
|---|---|
| Python | 8 МБ |
| **aiogram 3.31** | **+157 МБ** |
| SQLAlchemy | +16 МБ |
| asyncpg | +3 МБ |
| redis | +6 МБ |
| код бота | +6 МБ |
| **Процесс бота итого** | **≈196 МБ** |

Главный расход — не код бота, а сам aiogram: Bot API 10.3 описывает
несколько сотен типов, и все они разворачиваются в модели pydantic при
импорте. Уменьшить это, не отказываясь от библиотеки, нельзя.

Полный набор на одном сервере:

| Процесс | Память |
|---|---|
| Бот | ≈200 МБ |
| PostgreSQL | 80–120 МБ |
| Redis | 10–20 МБ |
| Система (Ubuntu) | 150–250 МБ |
| **Итого** | **≈450–600 МБ** |

### Что брать

| Сценарий | Характеристики | Ориентир цены |
|---|---|---|
| Минимум для 3–5 чатов | 1 vCPU, 1 ГБ RAM, 20 ГБ SSD, **+2 ГБ swap** | 4–6 $ |
| **Рекомендую** | 2 vCPU, 2 ГБ RAM, 25–40 ГБ SSD | 6–10 $ |
| Запас до 50+ чатов | 2 vCPU, 4 ГБ RAM, 40 ГБ NVMe | 10–14 $ |

На 1 ГБ бот работает, но при обновлении образа и одновременной работе
PostgreSQL память кончается. Swap спасает, однако отклик проседает.
**В 10 $ уверенно укладывается вариант на 2 ГБ — берите его.**

Прочее:

* **Диск.** 20 ГБ хватает надолго: база пустого чата занимает единицы
  килобайт, чат на 5000 участников — около 1 МБ. Растёт только история
  репутации и наказаний.
* **Расположение.** Европа (Германия, Нидерланды, Финляндия) — там
  ближе всего серверы Telegram, отклик 5–20 мс против 100+ мс из-за
  океана.
* **Система.** Ubuntu 24.04 LTS. Ставится Docker, остальное поднимает
  `docker compose`.
* **Сеть.** Требований почти нет: бот сам ходит к Telegram, входящие
  соединения не нужны, домен и сертификат не требуются.

### Работа с телефона

Ежедневное управление ботом происходит **в самом Telegram** — панель
настроек, тексты, модули, списки слов. Сервер нужен только для
установки и обновлений.

| Задача | Как с телефона |
|---|---|
| Установка | SSH-клиент: Termius (Android/iOS), JuiceSSH, Blink |
| Обновление | `cd /opt/linkermor && git pull && docker compose up -d --build` |
| Обновление без SSH | GitHub Actions по push — достаточно нажать Merge в приложении GitHub |
| Запасной вход | веб-консоль провайдера прямо в браузере |
| Резервные копии | `pg_dump` по расписанию с отправкой файла вам в Telegram |

Последний пункт стоит сделать модулем бота: копия базы приходит вам
личным сообщением, и восстановление не требует ни компьютера, ни
файлового менеджера.

## 2. Как добавляется новый модуль

Модуль — это папка в корне проекта. Ядро при добавлении не меняется.

### Пример: модуль игр

```
mod_games/
├── spec.py        паспорт модуля
├── handlers.py    команды и callback
├── engine.py      жизненный цикл игры
├── base_game.py   базовый класс
├── dice.py        игры на кубиках Telegram
├── models.py      таблицы
├── repo.py        запросы
└── menu.py        пункты админ-панели
```

Файл `spec.py` объявляет модуль целиком:

```python
MODULE = ModuleSpec(
    name="games",
    priority=90,              # место в цепочке обработки
    router=router,            # хендлеры
    models=(Game, GamePlayer),# таблицы для миграций
    setting_defs=SETTINGS,    # настройки → в панель
    text_defs=TEXTS,          # тексты → в панель
    requires_perms=(),        # нужные права бота
)
```

Подключение — **одна строка** в `core/bootstrap.py`:

```python
from mod_games.spec import MODULE as games
return [chats, captcha, welcome, admin, moderation, antispam,
        triggers, reputation, ranks, games]
```

После этого автоматически, без единой дополнительной правки:

* хендлеры подключаются в порядке `priority`;
* настройки и тексты появляются в админ-панели;
* создаётся переключатель «включить модуль в этом чате»;
* `alembic revision --autogenerate` видит новые таблицы;
* архитектурные тесты начинают проверять и этот модуль.

Внутри модуля так же устроено добавление правил антиспама и игр: новый
файл и строка в списке. Ядро движка не трогается.

## 3. Команды

### В группе — для всех

| Команда | Что делает |
|---|---|
| `/rep [кто]` | репутация участника и место в чате |
| `/top` | участники с наибольшей репутацией |
| `/rank [кто]` | текущий ранг и сколько до следующего |
| `/ranks` | все ранги чата |

### В группе — модераторы и выше

Цель указывается тремя способами: ответом на сообщение, упоминанием или
числовым идентификатором.

| Команда | Пример |
|---|---|
| `/ban [кто] [срок] [причина]` | `/ban @spammer 7d реклама` |
| `/unban [кто]` | ответом на сообщение |
| `/mute [кто] [срок] [причина]` | `/mute 2ч флуд` |
| `/unmute [кто]` | `/unmute 123456789` |
| `/warn [кто] [причина]` | `/warn мат` |
| `/unwarn [кто]` | снять последнее предупреждение |
| `/warns [кто]` | сколько предупреждений действует |

Срок понимает `30m`, `2ч`, `1d12h`, `7д`, `навсегда`. Число без единицы —
минуты. Если первое слово не срок, вся строка считается причиной.

### В группе — администраторы чата

| Команда | Что делает |
|---|---|
| `/addtrigger <ключ>` | ответом на сообщение — оно станет ответом триггера |
| `/deltrigger <ключ>` | удалить триггер |
| `/triggers` | список ключевых слов |
| `/setwelcome` | ответом на сообщение — оно станет приветствием |
| `/delwelcome` | вернуть стандартное приветствие |
| `/welcome` | показать приветствие как его увидит новичок |
| `/addword <слово>` | запретить слово |
| `/delword <слово>` | разрешить слово |
| `/words` | список запрещённых слов |
| `/allowforward` | ответом на пересылку — разрешить её источник |
| `/denyforward` | ответом на пересылку — снова запретить |
| `/forwards` | белый список источников |
| `/addrank <порог> <название>` | добавить ранг |
| `/delrank <название>` | удалить ранг |

### В личке бота

| Команда | Что делает |
|---|---|
| `/start`, `/admin`, `/panel` | открыть панель настроек |
| `/cancel` | прервать ввод значения |

Команды `/kick` нет намеренно: исключение доступно только как
настраиваемое действие капчи и фильтров.

## 4. Панель владельца бота

Открывается той же командой `/start` в личке. Отличие от обычного
администратора одно, но важное: **в списке чатов видны все подключённые
чаты**, а не только те, где владелец состоит.

Владельцу доступно:

* открыть настройки любого чата и изменить что угодно;
* редактировать **глобальные тексты** — они действуют во всех чатах,
  которые не переопределили текст у себя;
* переименовывать разделы панели и подписи кнопок;
* ставить премиум-эмодзи и задавать цвета кнопок;
* создавать триггеры с регулярными выражениями (обычным
  администраторам это недоступно: выражение способно занять процессор
  надолго).

Владельцы задаются в `.env` переменной `OWNER_IDS` — это единственная
глобальная проверка прав во всём проекте.

## 5. Панель администратора чата

`/start` в личке бота → список чатов, где у человека есть права →
выбор чата → меню.

```
Настройка чата «Название»

[ Модули ]      что включено в этом чате
[ Настройки ]   параметры по разделам
[ Тексты ]      все сообщения бота
[ Другой чат ]  вернуться к списку
```

**Модули** — переключатели с цветом состояния: зелёная кнопка означает,
что модуль работает, красная — выключен. Выключенный модуль не отвечает
вовсе, его хендлеры для этого чата как будто не существуют.

**Настройки** сгруппированы по модулям. Логические переключаются
кнопкой, числовые и текстовые запрашивают значение сообщением.
Недопустимое значение отклоняется с объяснением, а не записывается.

**Тексты** — любое сообщение бота. Изменённые отмечены значком. При
открытии бот показывает текущий текст отдельным сообщением — ровно
таким, каким его видят участники, с форматированием и премиум-эмодзи.
Новый текст присылается обычным сообщением: оформление сохраняется.

Администратор чата A не видит чат B. Права проверяются заново при каждом
нажатии: если человека понизили, пока панель была открыта, следующее
нажатие будет отклонено.

## 6. Что происходит в чате

### Подключение

1. Бота добавляют в чат и выдают права администратора.
2. Бот создаёт запись чата, читает свои права, определяет
   администраторов и становится активным.
3. Тот, кто добавил бота, получает доступ к панели.

Если бота исключат, чат перейдёт в неактивное состояние, но **все
настройки, тексты, репутация и история сохранятся**. При возвращении
бота всё оживёт.

Переезд группы в супергруппу обрабатывается: данные переносятся на новый
идентификатор, ничего не теряется.

### Новый участник

```
вошёл → капча включена? ──да──→ мут + проверка ──пройдена──→ приветствие
                        └─нет──→ приветствие
```

При провале проверки применяется настроенное действие: мут, исключение с
правом вернуться или бан. Если бот лишён права ограничивать участников,
проверка пропускается — изображать её без возможности заблокировать
было бы обманом.

### Обычное сообщение

Порядок обработки задан явно и виден в одном месте:

```
1. служебные события      подключение, права, вход и выход
2. капча                  непрошедший дальше не идёт
3. приветствие
4. панель                 только в личке
5. модерация              команды администраторов
6. антиспам               7 правил, первое сработавшее останавливает
7. триггеры               ответы на ключевые слова
8. репутация              +/- ответом на сообщение
9. ранги                  пересчёт и поздравление
```

Команда администратора обрабатывается раньше антиспама и под фильтры не
попадает. Администрация по умолчанию вообще не подпадает под правила —
иначе модератор не смог бы процитировать нарушение при разборе.

## 7. Расход ресурсов и скорость

### Память

Основная часть — константа: 200 МБ на процесс независимо от числа чатов.
На чат добавляется немного:

| Что | Размер |
|---|---|
| Настройки чата в кеше | ≈1.8 КБ |
| Тексты чата в кеше | 0–10 КБ (только переопределённые) |
| Триггеры, ранги, слова | единицы килобайт |
| **Итого на чат** | **≈5–20 КБ** |

50 чатов добавят около 1 МБ. Память определяется библиотекой, а не
нагрузкой.

### Что сделано ради скорости

| Приём | Эффект |
|---|---|
| Пул соединений | нет подключения к базе на каждое сообщение |
| Кеш настроек и текстов | один запрос на чат вместо запроса на сообщение |
| Кеш правил антиспама и триггеров | проверки идут в памяти |
| Счётчики флуда в кеше | текст сообщений не хранится вовсе |
| Атомарные запросы | нет чтения перед записью для счётчиков |
| Частичные индексы | поиск активных наказаний не сканирует историю |
| Ограничитель отправки | нет блокировок со стороны Telegram |

Обработка сообщения, не вызвавшего реакции, — это две операции в памяти
и ни одного запроса к базе, кроме учёта активности. Отклик ограничен
сетью до Telegram, а не ботом.

### Нагрузка на процессор

При 5 чатах — доли процента. Заметный расход дают только регулярные
выражения в триггерах, поэтому они доступны лишь владельцу, а длина
просматриваемого текста ограничена.

## 8. Чего не хватает и что стоит добавить

### Необходимое

| Что | Зачем |
|---|---|
| **Резервные копии базы** | сейчас их нет. `pg_dump` по расписанию с отправкой файла владельцу в Telegram — восстановление с телефона |
| **Уведомления об ошибках владельцу** | ошибки идут в лог на сервере, который с телефона не почитать |
| **Проверка живости** | если бот упал, вы узнаете об этом от участников |

### Сильно упростит жизнь при росте

| Что | Зачем |
|---|---|
| **Копирование настроек между чатами** | при 20 чатах настраивать каждый вручную мучительно |
| **Рассылка от владельца** | объявление сразу во все чаты |
| **Антирейд** | всплеск входов включает капчу и ужесточает фильтры автоматически |
| **Статистика чата** | сообщения по дням, активные участники, срабатывания фильтров |

### Полезные мелочи

* правила чата командой `/rules`;
* тихий режим для новичков: первые минуты без ссылок и вложений;
* белый список доменов вместо полного запрета ссылок;
* автоудаление служебных сообщений о входе и выходе (настройка уже есть,
  обработчик ещё нет);
* ночной режим с замедлением чата;
* поддержка тем в форумах — отложена по вашему решению;
* казахский и английский языки — схема к этому готова, колонка языка уже
  заложена.
