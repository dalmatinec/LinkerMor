# Чек-лист проверки

Пройдите по порядку. Каждый пункт — одно действие и один ожидаемый
результат. Если что-то не сходится, отметьте пункт и опишите, что
получилось на самом деле.

Для проверки удобно иметь **два тестовых чата** и второй аккаунт: часть
сценариев требует участника, который не является администратором.

## 4. Модерация

Проверяется вторым аккаунтом в чате А.

| № | Действие | Ожидается |
|---|---|---|
| 4.1 | `/warn` ответом | предупреждение 1 из 2 |
| 4.2 | `/warn` ещё раз | порог достигнут, выдан мут |
| 4.3 | — | счёт предупреждений обнулился |
| 4.4 | `/unmute` ответом | участник снова может писать |
| 4.5 | `/mute 2ч флуд` ответом | мут на 2 часа, в тексте «2 часа» |
| 4.6 | `/ban @username` | блокировка по имени |
| 4.7 | `/ban 123456789` | блокировка по идентификатору |
| 4.8 | `/unban` ответом | разблокирован, **не выкинут из чата** |
| 4.9 | Попробовать `/ban` на другом админе | отказ |
| 4.10 | Попробовать `/ban` на себе | отказ |
| 4.11 | Команда модерации от обычного участника | бот не реагирует |

| № | Действие | Ожидается |

| 10.1 | В чате А включить приветствие, в чате Б выключить | работают по-разному |

| 10.5 | Перезапустить бота | все различия сохранились |

## Как описать найденное

Чем точнее, тем быстрее исправлю:

```
Пункт 6.8
Что сделал: переслал сообщение из канала «Новости»
Ожидал: удаление и мут
Получил: сообщение осталось, бот промолчал
Чат: супергруппа, бот администратор, право удаления есть
```

Полезно приложить кусок лога: `docker compose logs --tail 50 bot`.
