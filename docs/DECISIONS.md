# Технические решения

Решения, принятые при проектировании, и причины — чтобы к ним не возвращаться.

## Зависимости

| Решение | Причина |
|---|---|
| aiogram 3.31.0 вместо 3.30.0 из ТЗ | 3.31 поддерживает Bot API 10.3; 3.30 — только 10.2 |
| Redis включён | состояния FSM между перезапусками, счётчики флуда со сроком жизни, токены callback. Для инвалидации кеша при одном экземпляре не требуется |
| Логирование на стандартном `logging` | отдельная библиотека ради формата логов не нужна |
| PostgreSQL, а не SQLite, в том числе в тестах | нужны JSONB, частичные индексы, `ON CONFLICT` |

## Архитектура

| Решение | Причина |
|---|---|
| Вертикальные модули `mod_*`, а не слои | масштабирование: новый модуль не трогает ядро |
| `priority` в `ModuleSpec` вместо порядка импортов | порядок обработки виден в одном месте и не ломается при перестановке строк |
| Дефолты настроек в реестре кода, в базе только переопределения | новая настройка не требует миграции; сохранение после перезапуска получается само |
| Канонический формат контента — `text + entities` | именно это приходит от администратора и принимает `sendMessage`. `sendRichMessage` подключается отдельным рендерером |
| Один экземпляр приложения | 50+ чатов — малая нагрузка для асинхронного процесса; распределённые локи и pub/sub не нужны |

## Ограничения Telegram, учтённые в проекте

| Ограничение | Как обходится |
|---|---|
| Нет метода «`@username` → `user_id`» | собственный справочник пользователей, виденных ботом, плюс `text_mention` и числовой ID |
| `callback_data` ≤ 64 байт | контекст чата живёт в FSM-сессии; длинные данные — через токен в Redis |
| `chat_member` не приходит по умолчанию | явный `allowed_updates` при запуске |
| Offsets entities считаются в UTF-16 | отдельный примитив `EntityText` с пересчётом позиций |
| Анонимные админы приходят от `GroupAnonymousBot` | считаются администраторами чата; персональный аудит невозможен |
| Сообщения от имени канала | отдельный метод `banChatSenderChat` |

## Решения по требованиям ТЗ

| Пункт | Решение |
|---|---|
| §17 Reply keyboard | отменён по решению заказчика: интерфейс полностью на inline-кнопках |
| §18 Цвета кнопок | нативные `style`, эмуляции нет |
| §7 `/kick` | команды нет; `kick` доступен как настраиваемое действие капчи и фильтров |
| §12 Метрика рангов | настраивается на чат: репутация, число сообщений или сумма |
| §13 Языки | пока только русский; колонка `lang` заложена в схему заранее |
| Белый список пересылок | блокируются все пересылки, кроме разрешённых источников |
